# Keputusan skema & keamanan (hal yang tidak tertulis di prompt)

1. **Hak akses minimum.** Semua tabel RLS aktif. `anon` tidak punya hak apa pun. `authenticated` hanya `select` (+ `insert` sesi pengukuran, `update` pengaturan/jadwal, `update(read_at)` notifikasi). `device_secrets`: RLS aktif tanpa policy dan tanpa grant.
2. **Logika inti hanya untuk service_role.** `finalize_session`, `mark_session_lost`, `ingest_telemetry`, `run_watchdog`, `classify_*`, `full_portion_kg` tidak bisa dipanggil klien (diuji).
3. **Sesi dibuat klien, tapi dikunci trigger.** `session_defaults` memaksa status `menunggu_drone`, mengisi `session_no` (hasil hari ini + 1, maks. sesi/hari) dan membatalkan sesi aktif lama. Indeks unik parsial menjamin maks. satu sesi aktif per kolam. "Coba lagi" = insert sesi baru.
4. **Pembatalan & pakan lewat RPC** (`cancel_session`, `start_feeding_run`) karena klien tidak boleh `update` sesi atau `insert` `feeding_runs`. `start_feeding_run` menolak bila izin terbang terkunci dan mengembalikan run yang sama bila dipanggil ulang.
5. **Stabil = rentang 60 dtk terakhir.** Maks − min tiap parameter dalam 60 dtk terakhir harus ≤ ambang (DO 0,1 · pH 0,05 · suhu 0,1) dan data minimal mencakup 60 dtk. Selisih dua titik berjarak 1 menit (bunyi prompt) terbukti bisa lolos karena kebetulan sefase (ditemukan di tes: sesi selesai di detik 70 dan 180). Angka "Perubahan 1 menit" di layar tetap selisih sampel t dan t−60 sesuai prompt; yang menentukan selesai adalah rentang. Batas waktu `measure_minutes` tetap memaksa selesai.
6. **Pembulatan.** Rata-rata jendela 60 dtk dibulatkan 1 desimal sebelum diklasifikasi, supaya status sama dengan angka yang tampil.
7. **Telemetri atomik di SQL** (`ingest_telemetry`): upsert, hitung paket, ubah status, cek stabil, finalisasi dalam satu transaksi. Sampel ke sesi yang sudah tertutup dijawab `accepted:false`, bukan error, supaya alat tahu harus berhenti. Validasi rentang: DO 0–30, pH 0–14, suhu −5–60, baterai 0–100, maks. 200 sampel/permintaan.
8. **Zona waktu riwayat** hard-coded `Asia/Jakarta` (hari = hari WIB) di `daily_min_do`, `session_defaults`, dan seed.
9. **Watchdog:** sesi `berjalan` tanpa sampel > 30 dtk → `data_terputus`; perangkat > 60 dtk → `telemetry_ok=false`; run pakan tanpa update > 60 dtk → `terputus`. Dijadwalkan pg_cron bila tersedia; bila tidak, pakai Supabase Cron → Edge Function `session-watchdog`.
10. **Seed** mematikan trigger sesi sementara agar riwayat berstatus `selesai`. Pengguna demo `demo@aquadrone.test` hanya untuk lokal; **jangan jalankan seed di proyek produksi**.
11. **Kunci:** frontend hanya memakai Project URL + publishable/anon key. `service_role` dan kata sandi database tidak pernah ditaruh di repo.
12. **API perangkat.** Perangkat tidak membuat run pakan: run dibuat aplikasi (`start_feeding_run`, target = porsi hasil pengukuran) dan perangkat hanya memperbarui (`device-feed-progress`); tanpa run aktif jawabannya 404 `run_not_found`. `dispensed_kg` tidak pernah turun atau melebihi target. Poll mengembalikan sesi aktif + run pakan aktif + `resume_after_t_sec` agar alat yang restart bisa melanjutkan. Kunci perangkat berformat `adk_` + 64 hex; DB hanya menyimpan SHA-256-nya. Fungsi perangkat memakai `verify_jwt = false` (kunci publishable bukan JWT); watchdog memeriksa sendiri `Authorization: Bearer <service_role>`.

13. **Monitoring air & Kontrol pakan memakai klien anon tanpa sesi.** Policy RLS tabel `monitoring_air` dan `kontrol_pakan` (dibuat pengguna) hanya untuk role `anon`; pengguna yang login berperan `authenticated` sehingga tidak tercakup. Maka kedua fitur memakai klien terpisah (`persistSession:false`). Skema dan policy TIDAK diubah.
14. **Status air dihitung dari nilai mentah rata-rata** (tidak dibulatkan dulu), sama dengan yang wajar dilakukan ESP32 dengan float. pH/suhu batas AMAN inklusif, DO harus > 4,0; batas BAHAYA strict. Jika pH atau DO tidak bisa dirata-ratakan (semua kosong) status = "tidak lengkap" (bukan menebak). Suhu kosong di semua baris = BAHAYA (sesuai aturan).
15. **Deteksi respons ESP32 untuk perintah pakan:** `hasil` berubah, atau `persen_aktual` berubah, atau `updated_at` lebih baru dari baris sesudah perintah kita ditulis. Bila ESP32 menjawab dengan nilai yang persis sama dan tidak mengubah `updated_at`, jawabannya tidak terlihat dan UI menampilkan "Perangkat tidak merespons" setelah 10 dtk. Perintah yang ditimpa klien lain dihentikan tanpa error.
16. **Risiko keamanan yang ada di desain tabel (tidak diubah):** policy `anon update kontrol` menggunakan `true`, jadi siapa pun yang memegang kunci publishable (ada di aplikasi web) dapat mengirim perintah buka pakan. Disarankan nanti: batasi lewat login (`authenticated` + peran) atau Edge Function.
17. **Navigasi:** tab bawah menjadi 5 (Beranda, Air, Pakan, Riwayat, Pengaturan) agar fitur baru mudah dijangkau tanpa mengubah isi halaman lain.
